# D512 sentence scorer integration

`d512` is optional and disabled by default. It adds engine-side fusion and an
editor hook using only the standard library. It does not load ORT or a model.
The Windows TIP enables `d512`; its scoring host enables `d512-ort`.

## Scorer contract

```rust,ignore
use chewing::d512::{D512Error, SentenceRequest, SentenceScorer};
use std::time::Instant;

struct IpcScorer;
impl SentenceScorer for IpcScorer {
    fn score(&mut self, request: &SentenceRequest, deadline: Instant)
        -> Result<Vec<f64>, D512Error>
    {
        // Send context, reading, and candidates with the remaining time budget.
        // Return the corresponding host scores; do not retry or log the text.
        todo!()
    }
}
```

`SentenceRequest` has three public fields:

| Field | Type | Meaning |
|---|---|---|
| `context` | `String` | Confirmed text to the left, at most 64 Unicode scalar values. This is not preedit text. |
| `reading` | `Vec<String>` | 1–32 complete Zhuyin syllables in input order; first tone has no mark. |
| `candidates` | `Vec<String>` | Unique complete sentence texts in native order, at most 16 (currently at most 10 native paths before deduplication). Each text has one Unicode scalar per syllable. |

The scorer returns **one finite natural-log model score per candidate**, in
exactly the requested order. It must not return text, reorder candidates,
convert the score to log10, or incorporate engine weights. All candidates must
be scored successfully; an OOV or other fallback applies to the whole request.
The scorer may return `D512Error::{Oov, BadReading, OutOfLimits, InvalidModel,
MissingFiles, RuntimeUnavailable, Timeout, Busy, NonFinite, Inference}`.
`InvalidConfig` also represents an unusable score-vector shape. No error embeds
request text. Request and suggestion `Debug` output omit their text.

`deadline` is a local monotonic `Instant`. The implementation **must bound its
transport/inference by this deadline** and must not panic. An IPC implementation
sends the remaining duration, not an `Instant` serialized across processes, and
sets its own bounded connection/write/read deadlines. No retries are performed
by libchewing. The engine also discards a successful response arriving after
the deadline. It cannot preempt an arbitrary user implementation that ignores
the deadline; timeout enforcement is part of the scorer contract.

## Editor and engine API

`Editor` and `ChewingEngine` both expose:

```rust,ignore
set_sentence_scorer(
    &mut self,
    scorer: Option<Box<dyn SentenceScorer + Send>>,
    options: D512Options,
) -> Result<(), D512Error>
set_d512_context(&mut self, confirmed_left: &str)
d512_report(&self) -> Option<D512Report>
```

The editor retains the scorer when switching conversion engines through either
`set_editor_options` or `set_conversion_engine`. Standard `ChewingEngine` calls
the hook after decoding. Simple and fuzzy conversion retain their native
behavior and do not call the scorer. A direct `ChewingEngine` struct literal
needs `d512: Default::default()` when this feature is enabled.

```rust,ignore
use chewing::d512::{D512Mode, D512Options};
editor.set_sentence_scorer(Some(Box::new(ipc_scorer)), D512Options::default())?;
editor.set_d512_context(confirmed_text_before_composition);
// Normal editor operations now use the injected scorer.
// Disable without making any scoring/IPC call:
editor.set_sentence_scorer(None, D512Options {
    mode: D512Mode::Off, ..D512Options::default()
})?;
```

Defaults: mode `Automatic`, weight `0.25`, margin `0.25`, timeout **100 ms**.
Modes map to the C2 settings as follows: 0 `Off`, 1 `Automatic`, 2 `Suggestion`.
In this stage, `Suggestion` has automatic behavior; a UI and acceptance command
are not implemented. Nonfinite/negative weights or margins, zero timeout, or a
timeout above five seconds are rejected and detach any previously set scorer.
Feature default off and runtime default automatic are separate choices: a
compiled feature without a scorer always retains native conversion.

The engine builds its request from the native decoded paths, keeps the first
occurrence of each text, and leaves its original score and path intact. Fusion:

`fused = -outcome.cost + weight * model_logp`

Native costs are negative log10 scores. A non-default candidate moves to the
front only when its fused score exceeds the default by **strictly more than**
the margin. Other paths retain relative order. The engine never synthesizes a
candidate, changes a word, or edits composition selections. Every decoded
sentence is checked against all explicit `Composition::selections`; any mismatch
keeps the entire native order without calling the scorer.

Absent scorer, mode off, scorer error, invalid/nonfinite score vector, elapsed
deadline, unusable input, or a poisoned/busy state all retain the original path
order and native first choice. There is no scoring retry. Transport connection
and host-launch throttling belong to C2. Do not create/connect an IPC scorer
while mode is off.

`D512Report` describes the last scoring attempt: `selected_index` indexes the
original native outcomes, `candidate_indices` maps unique requests to those
outcomes, `model_scores` preserves scorer order, `fallback` gives the error
category, and `elapsed` measures the hook. `suggestion` contains the chosen
`text`, original `outcome_index`, and `fused_gap` when an override wins. It is
reserved for a future suggestion UI. Setting context/configuration, clearing
composition, or committing invalidates the report. Callers must associate it
with their current composition and must not log or persist its text.

## Native ONNX backend

The `d512-ort` backend is being implemented in C1 stage 1. It will use `ort`
`load-dynamic`, an explicit caller-provided runtime path, pinned MIT model
`d512-pf512-20260926`, and the same trait. It is for the host/offline verifier;
the TIP must not enable it. Loading and fallback details will be finalized
with the backend verification.

## Calibration and validation

The balanced point is `(0.25, 0.25)` from the frozen A1 dev selection.
Conservative/aggressive presets await C1 stage 2; do not treat placeholders as
calibrated presets. Stage 1 validation requires A1 fixture score error at most
`1e-4` and the same 6,333 correct held-out sentences from the in-engine hook.

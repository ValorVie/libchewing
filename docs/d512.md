# D512 sentence scorer integration

`d512` is optional and disabled by default. It adds engine-side fusion and an
editor hook. It does not load ORT or a model. The editor also uses `serde_json`
for [personal candidate history](personal-candidate-preference.md), independently
of the D512 feature.
The Windows TIP enables `d512`; its scoring host enables `d512-ort`.
Build and inspect their dependency graphs separately: Cargo unifies features
of a shared dependency when both consumers are selected in one invocation.
Do not use a combined workspace build as proof that the TIP excludes ORT.
See [Cargo feature unification](https://doc.rust-lang.org/cargo/reference/features.html#feature-unification).

## Scorer contract

```rust,ignore
use chewing::d512::{D512Error, SentenceRequest, SentenceScorer};
use std::time::Instant;

struct IpcScorer;
impl SentenceScorer for IpcScorer {
    fn score(&mut self, request: &SentenceRequest, deadline: Instant)
        -> Result<Vec<f64>, D512Error>
    {
        // Send context, reading, and candidates with the remaining time budget.
        // Return the corresponding host scores; do not retry or log the text.
        todo!()
    }
}
```

`SentenceRequest` has three public fields:

| Field | Type | Meaning |
|---|---|---|
| `context` | `String` | Confirmed text to the left, at most 64 Unicode scalar values. This is not preedit text. |
| `reading` | `Vec<String>` | 1–32 complete Zhuyin syllables in input order; first tone has no mark. |
| `candidates` | `Vec<String>` | Unique complete sentence texts in engine order, at most 16 (up to 10 native paths plus an optional personal-preference default before deduplication). Each text has one Unicode scalar per syllable. |

The scorer returns **one finite natural-log model score per candidate**, in
exactly the requested order. It must not return text, reorder candidates,
convert the score to log10, or incorporate engine weights. All candidates must
be scored successfully; an OOV or other fallback applies to the whole request.
The scorer may return `D512Error::{Oov, BadReading, OutOfLimits, InvalidModel,
MissingFiles, RuntimeUnavailable, Timeout, Busy, NonFinite, Inference}`.
`InvalidConfig` also represents an unusable score-vector shape. No error embeds
request text. Request and suggestion `Debug` output omit their text.

`deadline` is a local monotonic `Instant`. The implementation **must bound its
transport/inference by this deadline** and must not panic. An IPC implementation
sends the remaining duration, not an `Instant` serialized across processes, and
sets its own bounded connection/write/read deadlines. No retries are performed
by libchewing. Do not reenter the owning editor from the scorer. The engine also discards a successful response arriving after
the deadline. It cannot preempt an arbitrary user implementation that ignores
the deadline; timeout enforcement is part of the scorer contract.

## Editor and engine API

`Editor` and `ChewingEngine` both expose:

```rust,ignore
set_sentence_scorer(
    &mut self,
    scorer: Option<Box<dyn SentenceScorer + Send>>,
    options: D512Options,
) -> Result<(), D512Error>
set_d512_context(&mut self, confirmed_left: &str)
d512_report(&self) -> Option<D512Report>
```

The editor retains the scorer when switching conversion engines through either
`set_editor_options` or `set_conversion_engine`. Standard `ChewingEngine` calls
the hook after decoding. Simple and fuzzy conversion retain their native
behavior and do not call the scorer. A direct `ChewingEngine` struct literal
needs `d512: Default::default()` when this feature is enabled.

```rust,ignore
use chewing::d512::{D512Mode, D512Options};
editor.set_sentence_scorer(Some(Box::new(ipc_scorer)), D512Options::default())?;
editor.set_d512_context(confirmed_text_before_composition);
// Normal editor operations now use the injected scorer.
// Disable without making any scoring/IPC call:
editor.set_sentence_scorer(None, D512Options {
    mode: D512Mode::Off, ..D512Options::default()
})?;
```

Defaults: mode `Automatic`, weight `0.25`, margin `0.5`, timeout **100 ms**.
`personal_bonus` and `suggestion_personal_bonus` each default to `2.0`; the active
mode uses its own field when the editor enables personal preference.
Modes map to the C2 settings as follows: 0 `Off`, 1 `Automatic`, 2 `Suggestion`.
`Suggestion` scores the same engine paths and reports the same model winner as
`Automatic`, but preserves the engine default until explicit acceptance. With
personal preference enabled, that default includes reversible personal choices. Producing or ignoring a
suggestion does not add selections or learn the suggested text; normal native
commit learning still follows the editor options. Nonfinite/negative weights, margins or personal bonuses, zero timeout, or a
timeout above five seconds are rejected and detach any previously set scorer.
Feature default off and runtime default automatic are separate choices: a
compiled feature without a scorer retains the engine default, including enabled
personal preferences.

The engine builds its request from the native decoded paths, keeps the first
occurrence of each text, and leaves its original score and path intact. Fusion:

`fused = -outcome.cost + weight * model_logp + personal_hits * bonus`

With personal preference enabled, the reversible personal path is the default;
otherwise the native first path is the default. Direct `ChewingEngine` use has
no personal store. Native costs are negative log10 scores. A non-default candidate moves to the
front only when its fused score exceeds the default by **strictly more than**
the margin. Other paths retain relative order. D512 never synthesizes a candidate, changes a word, or edits composition
selections. The editor may supply one extra dictionary-valid personal default
before this reranking step. Every decoded
sentence is checked against all explicit `Composition::selections`; any mismatch
keeps the entire native order without calling the scorer.

Absent scorer, mode off, scorer error, invalid/nonfinite score vector, elapsed
deadline, unusable input, or a poisoned/busy state all retain the original path
order and current first choice, including enabled personal preferences. There is no scoring retry. Transport connection
and host-launch throttling belong to C2. Do not create/connect an IPC scorer
while mode is off.

After text deduplication, fewer than two candidates need no scoring. The hook
returns every native outcome unchanged and makes no scorer/IPC call, in either
enabled mode. For a single unique candidate the fresh report has
`selected_index = 0`, its first native index in `candidate_indices`, empty
`model_scores`, and neither `suggestion` nor `fallback`. This is a normal skip,
not an inference failure. It also avoids rescoring when display getters decode
an accepted suggestion whose entire path is now explicitly selected.

`D512Report` describes the last hook evaluation: `selected_index` indexes the
original native outcomes, `candidate_indices` maps unique requests to those
outcomes, `model_scores` preserves scorer order, `fallback` gives the error
category, and `elapsed` measures the hook. `suggestion` contains the chosen
`text`, original `outcome_index`, `fused_gap`, and changed word intervals when an
override wins. It is present only when a non-default model winner exceeds the
margin and at least one eligible word interval changed, in either
enabled mode. In `Suggestion`, these indices describe a proposal, not a moved
or accepted path. Changing normalized context/configuration, clearing
composition, or committing invalidates the report. Callers must associate it
with their current composition. Text may be persisted only through the caller's
explicitly enabled local calibration collection described below.

### Changed words for suggestion hints

`D512Suggestion::text` remains the **full winning sentence**, used to validate
acceptance. `changes: Vec<D512Change>` supplies only the changed winning words
for a hint, in winning-path order. Each public `D512Change` has `start: usize`,
`end: usize`, and `text: String`. The half-open `start..end` range uses composition
symbol/syllable indices, matching `Interval`; these are not UTF-8 byte or UTF-16
offsets.

For each winning interval, the hook compares the original native first path.
It excludes the interval if the first path has the same start, end, and text,
or if its range overlaps any explicit selection. Adjacent ranges do not overlap.
Changing segmentation counts as a change even when some characters are the
same: replacing one two-symbol word with two one-symbol words lists both new
words. Identical text elsewhere in the sentence does not make an interval
unchanged. No substring diff or new word segmentation is performed.

The caller formats the Mac-style hint from these words:

```rust,ignore
let words = suggestion.changes.iter()
    .map(|change| change.text.as_str()).collect::<Vec<_>>().join("／");
let hint = format!("⇥ {words}");
```

Both Automatic and Suggestion populate this metadata. If no eligible intervals
remain, `D512Report::suggestion` is `None`; the selected index and Automatic
reranking still follow the original fusion decision. In Suggestion, calibration
`suggested` is false when there is no proposal. Acceptance still uses the saved
**complete** winning path and full sentence, not this filtered hint. Cached
successful results retain the same changes without another scoring call.
`Debug` for a change prints its range only; suggestion/report Debug omit text.

### Reusing the current result

The hook retains one successful scoring result for the current input. Repeated
display queries and Enter commit use that result without another scorer/IPC
call when all of these still match:

- composition symbols, gaps, explicit selections, and committed-prefix origin;
- confirmed-left context after keeping its last 64 Unicode scalar values;
- mode, weight, margin, and timeout;
- the entire native outcome vector, including order, costs, interval ranges,
  phrase flags, and text.

`set_d512_context()` with the same normalized context preserves the report and
calibration snapshot. Automatic reapplies the saved selected index to the
matching native paths; Suggestion retains native order and its saved proposal.
Thus a later unavailable scorer cannot replace an already displayed successful
choice while committing that same input. Commit still clears the composition
and its snapshots, and normal native learning uses the committed path.

A matching result retains its original report, scoring time, calibration data,
and suggestion path. Reuse is not a new scoring attempt or calibration event.
Only one input is retained: a miss discards it before normal scoring. Errors
and single-candidate skips do not populate the cache.
Changing context, reconfiguring/detaching the scorer, switching converters, or
clearing composition invalidates it. Composition and native-path changes cause
a miss even when the new text or length looks the same. Debug omits cached text.

### Calibration data

With `d512`, `Editor` additionally exposes:

```rust,ignore
d512_calibration(&self) -> Option<D512Calibration>
```

This clones the latest completed **actual scoring attempt**, including an
attempt that failed or exceeded its deadline. It uses the same composition
snapshot check as `d512_report()`: symbols/readings, gaps, explicit selections,
and committed-prefix origin must still match. Busy/poisoned state, stale data,
Off mode, absent scorer, a single unique candidate, or input rejected before
scoring returns `None`. A skipped evaluation replaces any prior data. Reading
this getter never scores, consumes a record, writes a file, or sends IPC.

The public `D512Calibration` fields are:

| Rust field | Meaning / JSON mapping for the caller |
|---|---|
| `reading: Vec<String>` | Normalized request syllables, in composition order; `reading` |
| `candidates: Vec<D512CalibrationCandidate>` | First-occurrence engine text order, deduplicated before scoring |
| `default_index: usize` | Always 0 in this candidate vector; `defaultIndex` |
| `winner_index: usize` | Highest fused score **before** the margin test, first index on ties; `winnerIndex` |
| `applied: bool` | Automatic moved the non-default path after `gap > margin` |
| `suggested: bool` | Suggestion proposed a non-default path after `gap > margin` |
| `weight: f64`, `margin: f64` | Active parameter pair |
| `mode: D512Mode` | Active Automatic or Suggestion mode |
| `bonus: f64` | Effective personal bonus for this mode; zero when personal preference is off |

Each `D512CalibrationCandidate` contains `text: String`, `raw: f64`
(`-outcome.cost`, engine log10), `personal_hits: usize` (`personalHits`),
`model_logp: Option<f64>` (`modelLogP`), and
`fused: Option<f64>`. Valid scores give
`fused = raw + weight * model_logp + personal_hits * bonus`.
Scorer errors, late responses, invalid lengths, or nonfinite scores leave
**all** `model_logp` and `fused` values `None`; the caller serializes them as
JSON null. Their winner is the default and neither decision flag is set.
These indices address the calibration candidate vector, not native outcome
indices: deduplication can make them differ from `D512Report::selected_index`.
A fused winner below the margin can differ from the default while both flags
remain false. `suggested` also requires a proposal with an eligible changed
word; it is false in Automatic. `applied` is false in Suggestion.

One actual scorer invocation provides one snapshot; later attempts overwrite
it. Repeated reads return that same snapshot, so collection must associate one
caller-owned ID with each completed attempt. Capture the owned value before
acceptance, edits, commit, cancel, or a converter/context/configuration change
makes the snapshot stale. A newly confirmed personal-history event also makes
the previous personal scoring snapshot stale. Accepting a suggestion does not mutate an already
captured value; the caller tracks acceptance and the final commit/cancel phase.
Single-candidate evaluations make no scoring attempt and provide no calibration
record, even when a fresh skip report is available.

The engine assigns no `id`, `phase`, `accepted`, or `finalCommittedText`. C2
owns those fields, serialization, the opt-in switch, and bounded local I/O.
Use the engine-provided `personal_hits` and `bonus` values; they are no longer
placeholder zeros. The caller owns `personalConflict` and `pomConflict`; this
API does not assign either conflict flag. Personal learning and delivery
confirmation are documented in [personal candidate preference](personal-candidate-preference.md). For compatibility with the Mac producer and analysis script, serialize
Suggestion as **`"suggest"`** and Automatic as `"automatic"`.

Both calibration types implement text-redacted `Debug`: neither readings nor
candidate text is printed, including when candidates are formatted separately.
The owned values still contain sensitive text. Merely enabling `d512` or reading
this API does not authorize persistence; callers collect/send records only when
their local calibration switch is on. No logging dependency is added to `d512`.

### Accepting a suggestion

With `d512`, only `Editor` additionally exposes:

```rust,ignore
accept_d512_suggestion(&mut self) -> bool
```

This accepts the **current fresh** proposal only in `D512Mode::Suggestion`.
The editor checks the report snapshot again, including symbols/readings,
gaps, explicit selections, and committed-prefix origin. It uses the actual
winning path's intervals and word IDs saved during that scoring attempt; it
does not insert the report text as a candidate or perform another inference.

All choices are prepared on an owned composition copy. The path must cover
the entire composition in order, resolve to the reported text using existing
word IDs, and retain every previous explicit selection at the same range and
word ID. Only then does the editor replace its composition. On success it
returns `true`, keeps the cursor and composition active, adds explicit choices, and emits
no commit. The changed composition makes the old snapshot stale, so immediate
repeated acceptance returns `false`. Ordinary later commit learning follows
the same options and rules as manual selection; acceptance itself does not
learn or write a user dictionary.

It returns `false` without changing the editor when:

- The mode is `Off` or `Automatic`, or no fresh suggestion exists (including
  scorer absence, fallback, no non-default winner, or a changed composition).
- A syllable is unfinished, the editor is not in its normal entering state,
  or the scorer state is busy or poisoned.
- The saved path is unavailable, malformed, cannot resolve its word IDs,
  conflicts with an explicit selection, or would make no composition change.

The caller handles focus/context identity, visible suggestion ownership, key
modifiers, and cursor eligibility. This API does not dispatch or consume keys.
In normal nonempty Chinese preedit without an unfinished syllable, C2 uses
`D512SuggestionAcceptKey` with the Mac-style rules:

| Value | Acceptance gesture | When acceptance returns `false` |
|---|---|---|
| 0 (default) | Tab with no modifiers | Consume the key without editing. |
| 1 | Ctrl+Tab with only Ctrl | Consume the key without editing; plain Tab retains native behavior. |
| 2 | Right arrow with no modifiers, at composition end | Retain native right-arrow behavior. |

Other keys withdraw the caller's pending suggestion before native handling.
A cached report in the caller is not acceptance authority.

## Native ONNX backend

`d512-ort` includes `d512` and exports `OrtSentenceScorer`:

```rust,ignore
use chewing::d512::{OrtSentenceScorer, SentenceScorer};
let mut scorer = OrtSentenceScorer::load(model_directory, absolute_runtime_library)?;
let model_scores = scorer.score(&request, deadline)?;
```

The host loads this scorer once and serializes access to it. Preserve each
request's remaining deadline while waiting for the scorer; expired requests
must not begin inference. Returning `Busy` is preferable to an unbounded queue.
The TIP enables only `d512` and supplies its IPC implementation of the trait.
Loading is a host initialization operation, outside the request deadline. On a
load error the host returns an error to clients; a TIP without a scorer, or
receiving that error, retains native conversion.

The runtime is `ort = 2.0.0-rc.14` with `std`, `load-dynamic`, and `api-31`,
without default features, binary downloads, or static linking. The caller must
provide an existing **absolute library-file path** for ONNX Runtime 1.31+.
There is no search for ORT in System32, PATH, or the working directory, and no
fallback to `ORT_DYLIB_PATH`. Initialize this backend before using any other
ORT API in the process. A different canonical runtime path in the same process
is rejected; repeated loads with the same path share the environment.
ONNX Runtime **1.31.0 CPU** is the validated release.

Launch the host with **`ORT_DISABLE_TELEMETRY=1` already set**, before any ORT
initialization. Otherwise `load` returns `TelemetryNotDisabled`. The library
does not mutate a multithreaded process environment: Rust 2024 marks that
operation unsafe on Unix. The created ORT environment also disables telemetry
through its API. This feature follows the crate's existing `deny(unsafe_code)`.

The caller supplies the immutable model directory; no model is downloaded or
located through a user-profile search. The MIT checkpoint is
[`d512-pf512-20260926`](https://huggingface.co/Funmula/0c-sequence-d512/tree/d512-pf512-20260926).
All three files must exist and match these SHA-256 values before a session is
created. Changing metadata or neutral-tone rules also invalidates the package.

| File | SHA-256 |
|---|---|
| model.onnx | `71af1f0e77b2752cc71cbc04bf19c8e8f2e765662246f766e65a2822bab4e66e` |
| vocab.json | `556dffaffbf4c05211a846dcee55ef735cea68c5754f9bffcc6f9588124172b3` |
| manifest.json | `f8d737cf44e9ff8f90e7108f1e9df4fece0cdcae254e050968fc6ef723ee1976` |

Session settings match the A1 harness: explicit CPUExecutionProvider with the
CPU arena enabled, graph optimization `All`, intra-op 2, inter-op 1. In ort
rc.14, `Level3` means layout optimizations, **not** `All`; using that name does
not reproduce the harness default.

The tensor protocol follows the MIT model card and the A1 harness: nine named
tensors, unknown context characters represented by UNK, and the last 64 Unicode
scalar values of confirmed context. Candidate OOV, invalid readings, or input
limits fail the entire request. A neutral-tolerant final syllable with any
non-neutral tone gets an extra neutral-tone inference; use the larger logP.
For one syllable with confirmed context, use the harness text task without
reading slots. With no confirmed context, use phonetic scoring. The caller's
weight/margin still apply; the backend never applies implicit text weights or
fusion. This extends the Swift reference's multi-syllable-only scope as
explicitly required for the harness protocol.

Each call uses fresh `RunOptions`; a deadline watchdog requests cooperative ORT
termination. The scorer also checks the deadline between candidate runs and
after completion. All errors and nonfinite outputs become `D512Error`, never a
partial score vector. A canceled run does not cancel later requests. Native
termination is cooperative; the IPC client must still enforce its own hard
transport deadline and discard late replies.

Native loading and protocol references: [ort dynamic linking](https://github.com/pykeio/ort/blob/main/docs/content/setup/linking.mdx),
[ORT thread management](https://onnxruntime.ai/docs/performance/tune-performance/threading.html),
and [Rust 2024 environment safety](https://doc.rust-lang.org/edition-guide/rust-2024/newly-unsafe-functions.html).

## Calibration and validation

### Current presets

<a id="automatic-presets"></a>
<a id="suggestion-presets"></a>

The user chose the **Mac A2.8 margins**, with chewing's weight **0.25** shared
by all six presets. Both modes default to balanced. These are fixed deployment
choices; the following offline reports do not select or optimize them.

| Mode | Conservative (`w`, `tau`) | Balanced, default (`w`, `tau`) | Aggressive (`w`, `tau`) |
|---|---|---|---|
| Automatic | (0.25, 1) | (0.25, 0.5) | (0.25, 0.2) |
| Suggestion | (0.25, 3) | (0.25, 2) | (0.25, 1) |

C2 uses `D512Weight` / `D512Margin` for Automatic and `D512SuggestWeight` /
`D512SuggestMargin` for Suggestion, passing the active pair in `D512Options`.
`D512Options::default()` creates Automatic balanced `(0.25, 0.5)`; callers
selecting Suggestion supply its balanced pair `(0.25, 2)`. Switching modes
retains the other mode's stored parameters. All presets use the standard
maximum of 10 native paths, followed by first-occurrence text deduplication.
The single-syllable text task uses the same active weight and margin.

Reusing the preserved factory-only scores, Automatic balanced has 1,605/1,794
correct dev requests and 6,319/7,189 correct held-out requests (+2.91 pp over
held-out native baseline). This is a cached-score report, not a new full model
inference or a new timing measurement. The original 3 pp gain threshold was
established at the former `(0.25, 0.25)` point; the new default does not reach
that threshold. The user-fixed presets remain unchanged by these results.

For suggestion reports, let H, D, N mean helpful, harmful, and neutral changes:

- Helpful: the native default is wrong and the proposed candidate is correct.
- Harmful: the native default is correct and the proposal is wrong.
- Neutral: native and proposal are both wrong, but their texts differ.

A proposal requires a non-default fused winner with **strictly `gap > tau`**.
The Mac-style comparison ratio is `H / (H + D)`; all-proposal precision is
`H / (H + D + N)`, counting neutral proposals as incorrect. A zero denominator
is undefined. Suggestion balanced has 20 dev proposals (14/1/5 H/D/N), giving
93.33% / 70.00% respectively; held-out has 108 proposals (74/2/32), giving
97.37% / 68.52%. Neither ratio measures acceptance rate or actual UI disruption.
Without acceptance, Suggestion still displays and commits native output.

### Backend validation

Backend fixture score error must remain at most `1e-4`. Historical in-engine
agreement with 6,333 correct held-out requests refers explicitly to weight
`0.25`, margin `0.25`, and the original fixed data. Reproduce that point with
explicit parameters; it is separate from the current default. The fixed
presets were evaluated on preserved dev and held-out scores without new model
inference, parameter selection, or personal-dictionary input. Future Windows
daily-use evidence may inform a later adjustment.

Metric references: [precision definition](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.precision_score.html)
and [Introduction to Information Retrieval, chapter 8](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-unranked-retrieval-sets-1.html).

Synthetic tensor/score oracle (no model or private corpus is vendored):

```sh
python examples/d512_fixture.py --harness /path/to/d512eval.py \
  --model-dir /path/to/model --out /new/path/oracle.json
ORT_DISABLE_TELEMETRY=1 D512_MODEL_DIR=/path/to/model \
  D512_ORT_LIBRARY=/absolute/path/to/runtime-library \
  D512_FIXTURE=/new/path/oracle.json \
  cargo test -p chewing --features d512-ort a1_tensor_and_score_fixture -- --ignored --nocapture
```

Build the verifier with `cargo build --release -p chewing --features d512-ort --example d512_dump`.
Its two-argument invocation retains native evaluation.
Four arguments add `MODEL_DIR ABSOLUTE_ORT_LIBRARY` and use the default 100 ms
deadline; a fifth argument sets the explicit timeout in milliseconds (maximum
5,000). Two further arguments specify `WEIGHT MARGIN`, after the timeout; they
must be supplied together. For example, trailing `5000 0.25 0.25` reproduces
the historical point, while `5000 0.25 0.5` selects current Automatic balanced.
Omitting both uses the library defaults. The verifier exports native-order
candidates for A1 compatibility and
records the **actual in-engine winner** under `d512.selected_text`, plus native
scores, fallback, and separate scoring/hook/conversion times. It excludes three
warmups. Offline equivalence to the untimed A1 reference uses an explicit
5,000 ms limit; this does not validate the 100 ms IPC path. Never use held-out
results to choose weights or margins.
